MyCasaPro

Operações de reparação Acesso seguro a prestadores Em laboratório

Projeto de Armel Tenkiang.

Visitar MyCasaPro Projetos

MyCasaPro é um sistema privado para coordenar reparações domésticas entre proprietários e prestadores. Uma interface Next.js 16 e React 19 funciona sobre uma API HTTP em Go e PostgreSQL. O sistema cobre imóveis, pedidos, anexos privados, orçamentos, marcações, mensagens, faturas e histórico de pagamentos.

Utilização

  • Os proprietários criam registos privados e pedidos com fotografias ou PDFs.
  • Os prestadores recebem pedidos, enviam orçamentos detalhados, marcam trabalhos, trocam mensagens e emitem faturas.
  • Um prestador sem conta pode consultar uma única reparação e enviar um orçamento através de um convite temporário.

Sistema

  • Sessões HTTP-only e autorizações por função separam o acesso de proprietários, prestadores e convidados.
  • Os anexos privados passam por rotas API autorizadas, não por URLs públicas.
  • Os links de convidado usam tokens aleatórios de 256 bits; apenas o hash SHA-256 é guardado, e cada link expira ou pode ser revogado.
  • Os convites por email são gravados numa outbox PostgreSQL antes do envio SMTP, com bloqueio, tentativas limitadas e estado de entrega.
  • O mesmo código suporta uma appliance privada limitada a localhost e uma base documentada para implantação num único servidor.

Integração com Galidima

MyCasaPro não está ligado diretamente ao Galidima. A fronteira prevista é uma projeção revogável e só de leitura de projetos, prestadores e orçamentos; a aplicação continua a ser a fonte de registo.

Quadro técnico

Restrição
Uma reparação reúne registos privados da propriedade, anexos e prestadores que podem não ter conta. O acesso tem de ser limitado sem bloquear orçamentos, marcações e aprovações.
Fronteira
A API Go controla autorização, persistência PostgreSQL e anexos privados. Os links dos prestadores são revogáveis, expiram e apenas o hash do token é guardado.
Verificação
A criação do convite e a fila de email são gravadas em conjunto. Um worker com bloqueio, tentativas limitadas e estado de entrega evita que uma falha SMTP elimine o acesso do prestador.

Estado atual

Em laboratório. O fluxo entre proprietário e prestador, os anexos privados, os orçamentos sem conta, a appliance local e a base de implantação num servidor estão implementados. Um lançamento mais amplo ainda exige monitorização externa, ensaios de recuperação fora do servidor, controlos antiabuso, armazenamento privado escalável e integração com um prestador de pagamentos real.
